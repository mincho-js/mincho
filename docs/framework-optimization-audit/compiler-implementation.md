# Compiler 계열 조사 항목의 Mincho 구현 상태

작성: 2026-09-24. [원본 조사](./compilers.md)의 **92개 ID 전체**(WyW 27, UnoCSS 30, devup-ui 35)를 추적한다. 원본 조사 문서는 변경하지 않았다. 이 표는 다른 프레임워크 기능을 그대로 복제했다는 뜻이 아니라, 현재 Mincho에서 확인한 대응 범위와 남은 경계를 기록한 것이다.

상태는 다음 의미로 사용한다.

- **기존 대응**: 작업 이전부터 있는 Mincho 소스·회귀 테스트를 확인했다. 원본 프레임워크와 API나 구현이 같다는 뜻은 아니다.
- **부분 대응**: 일부 메커니즘만 대응하며 표의 guard에 차이를 적었다.
- **구현·소스 검증**: 실제 구현과 아래에 명시한 workspace 소스 테스트 통과를 확인했다. 적용 범위는 해당 행의 동작·guard로 한정한다. 설치된 패키지·브라우저·성능 검증을 뜻하지 않는다.
- **구현·소스 확인**: 구현과 대응 테스트 파일을 읽어 연결을 확인했다. 이 문서에 실행 결과를 기록하지 않은 Vite 경로 등의 실행 검증은 별도로 구분한다.
- **measurement pending**: 현재 native bundler에 위임하는 판단 등에서 추가 측정이 필요하다.
- **미도입**: 직접 대응하는 구현을 확인하지 못했다. 해당 runtime/preset/framework 기능을 새로 추가했다는 주장을 하지 않는다.
- **excluded**: 이번 작업 범위에서 Oxc·Rust·WASM 도입을 제외한다. JavaScript에서 같은 원칙을 적용한 부분은 별도로 표시한다.

증거 열의 `E01` 등은 바로 아래 코드/테스트 목록을 가리킨다. 테스트 파일 링크만 있는 항목은 **소스 확인**이며 실행 통과를 주장하지 않는다. 최종 release build 뒤 Babel·Integration 전체 소스 테스트를 다시 실행했으며, 각 결과와 아직 별도 검증이 필요한 영역은 문서 끝에 기록했다. 원본 프레임워크의 더 넓은 기능 전체가 구현됐다는 의미로 상태를 확대 해석하지 않는다.

Vite/esbuild가 사용하는 [optimization mode](../../packages/integration/src/optimizationMode.ts#L6)는 production에서 `pureFunctions`, `staticRecipes`, `styledComponents`, `runtimeCodegen`, `jsxRuntimeGuards`를 켠다. development의 기본값은 `pureFunctions`만 켜며 개별 명시 설정이 우선한다. `dependencyGraph`·`staticStyles`는 5회 반복 측정에서 일반적인 초기 빌드 이득이 확인되지 않아 두 환경 모두 opt-in으로 제공한다. Vite client `appCss.mode: "dist-chunk"`의 CSS 최적화는 `appCss.optimize: true` 또는 옵션 객체를 명시할 때 `mergeRules`·`pruneGenerated`·`compactThemes`·제한된 `shareAtoms`를 켜며 [개별 설정](../../packages/vite/src/appCss.ts#L34)을 유지한다. 두 환경 모두 `appCss.optimize`를 생략하면 CSS 최적화는 비활성이다. `globalAtomicClasses`·`compileClass`와 compiler worker 활성화도 opt-in을 유지한다. 조건별 결과는 [측정 기록](./compiler-results.md)에 정리했다.

E23의 두 옵션은 기본값이 꺼진 실험 기능이다. 현재 compiler 후보는 `@mincho-js/css`의 `css`로 감싼 **단일 원소 composition** `css([privateOwner.css({ color: "red", display: "flex" })])`이다. private `defineRules`에서 `{ css: atomic }`으로 구조 분해한 경우의 `css([atomic(literal)])`도 허용한다. 호출 결과는 intrinsic JSX의 유일한 `className`으로 직접 사용하거나, 그 용도로만 참조되는 최상위 `const`에 저장해야 한다. `mincho$(owner.css(...))` 직접 호출은 이 compiler pass의 지원 후보가 아니다.

owner 전체가 닫힌 literal configuration과 허용된 독립 longhand 값으로 구성되어야 한다. 여러 composition 원소·별도 debug argument·동적 값·export·cx/preset·selector·custom component·JSX spread·추가 CSS의 관찰 가능성이 있으면 기존 scoped 경로를 유지한다. 증명된 호출은 build-only helper로 바뀌고 sidecar 추출 후 미사용 owner factory/import를 제거한다. `globalAtomicClasses`의 이름 공유 범위는 같은 원본 파일 domain이며, `compileClass` 결과는 독립적으로 제거 가능한 cx atom으로 공개하지 않는다. [installed consumer fixture](../../scripts/package-contract/fixture/modules/compiler-classes.mjs#L11)도 이 composition 문법으로 작성되었으며 실행 결과는 설치된 패키지의 package-contract 검증에서 별도로 기록한다.

## 구현 범위와 검증 결과

`createVar`/theme 생성 시 private variable ownership을 수집하고 serialized export의 public references와 함께 IR에 기록하는 실제 경로를 확인했다. liveness는 살아 있는 owner들 사이의 alias/cycle을 따라가며 author variable, public/escaped reference, inherited variable, 일반 외부 CSS가 관찰할 수 있는 값을 보존한다. `@property` 제거는 비상속이 증명된 generated 자원만 대상으로 한다. transition/animation, 해석할 수 없는 escape, 누락된 provenance도 보수적으로 유지한다. `mergeRules`/`compactThemes`는 같은 원본 파일의 인접한 flat equal rules만 합치고 class 이름은 유지한다.

`shareAtoms`는 native bundler와 기존 ordered **module-prefix** sharing을 연결한 범위다. cross-file의 임의 atom hoist/regroup/rename이나 전역 class identity 통합을 구현한 것으로 세지 않는다. single-importer 구조는 native bundler에 위임하며 별도 module rewrite를 추가하지 않는다. `light-dark()` lowering도 미도입이다. 일반 scoped cx 조건 table은 [현재 codegen](../../packages/babel/src/defineRulesCxConditionsCodegen.ts#L83)처럼 module 초기화의 `cx(...)` 호출을 유지한다. 기존 generic literal cx/finite recipe folding 및 private compound class 추출과 별개이며, scoped table 전체의 build-time string bake는 이번 compiler 계열 구현으로 집계하지 않는다.

소스 테스트는 **mise Node 24.21.0**에서 실행했다. 예를 들어 Integration은 `mise exec -- yarn workspace @mincho-js/integration exec vitest run --exclude '**/_release/**'`를 사용한다. `_release`의 복사된 테스트는 원본 source suite에 중복 포함하지 않는다.
