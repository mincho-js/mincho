## 1. WyW-in-JS

이 checkout은 **Oxc-first v2**다. 과거 Linaria의 Babel 중심 동작을 그대로 설명하면 틀린다. parser/codegen은 Oxc를 사용하지만 graph/shaker/static evaluator 상당 부분은 TypeScript다. `transformSync`는 v2에서 오류를 내며 async `transform`이 실제 경로다. 기본은 `eval.strategy: 'hybrid'`, `globalCache: true`, `dangerousCodeRemover: true`, `useWeakRefInEval: true`, bundler resolver다. [기본 옵션](https://github.com/wyw-in-js/wyw-in-js/blob/2ee2b736aaeba4eed596031e8e5c912f0395ac4d/packages/transform/src/transform/helpers/loadWywOptions.ts#L148), [transformSync 제한](https://github.com/wyw-in-js/wyw-in-js/blob/2ee2b736aaeba4eed596031e8e5c912f0395ac4d/packages/transform/src/transform.ts#L144).

## 2. UnoCSS

기본 Vite mode는 `global`이다. `dist-chunk`는 build에서만 활성화되며 dev에서는 global dev plugin을 쓴다. 기본 static integration에는 브라우저 CSS 생성기가 들어가지 않는다. `@unocss/runtime`은 별도 제품 경로다. `dist-chunk`가 bundler가 지운 개별 JSX/class literal까지 완전 분석한다는 주장은 코드와 맞지 않는다. 살아있는 `chunk.modules`의 **저장된 원본 code 전체**에서 tokens를 추출하기 때문이다. [mode 선택](https://github.com/unocss/unocss/blob/93b642097a367f7e39a17bfcc386f52ef21442bd/packages-integrations/vite/src/index.ts#L45), [chunk code 선택](https://github.com/unocss/unocss/blob/93b642097a367f7e39a17bfcc386f52ef21442bd/packages-integrations/vite/src/modes/chunk-build.ts#L24).

## 3. devup-ui

기본 compiler는 Rust/Oxc → WASM → bundler plugin이다. 이 checkout에는 기존 atomization 외에 route-aware atom hoisting, single-importer collapse, Next/Turbopack prewarm/coordinator, allocation 절감이 추가돼 있다. **`singleCss: false`의 기본 per-file 원자 이름과 `singleCss`/atomHoist의 global 원자 이름은 다르다.** 기본 모드가 모든 파일의 equal declaration을 전역 dedupe한다고 말하면 틀린다. 또 `zero-runtime`은 CSS 생성 engine이 없다는 뜻이지 theme hook이나 generated styled wrapper가 전혀 없다는 뜻이 아니다.

## 4. Mincho 현재 구현과의 교차검토

비교 기준은 Mincho HEAD `33911861786b4ee634f637e5635a1049dfaea6e3`이며, 같은 조사에서 작성한 [Mincho baseline](mincho-baseline.md)과 [종합 후보 목록](../framework-optimization-audit.md)을 함께 참조한다. 이 보고서의 표에는 빌드 메커니즘 77개와 런타임·출력 경계 15개, 총 92개 ID가 있다. API가 다른 같은 목적의 메커니즘, 최적화 적용의 제한, 제거되지 않고 남는 runtime도 포함한 **감사 항목 수**이며 92개의 독립적인 속도 개선이나 도입 과제를 의미하지 않는다.

[compilation-performance.md](../compilation-performance.md), [preset-graph-performance.md](../preset-graph-performance.md), css-bundling.md (`docs/css-bundling.md:1`)의 설명을 실제 IR·Vite 소스와 대조했다. 이미 있는 것은 raw IR collection/cache, 실제 `renderChunk` membership에 따른 CSS 생성, generic route/layout 목록, whole-artifact sharing, bounded source/evaluation/compilation caches, worker opt-in, normalized preset graph다. 이들을 새 UnoCSS dist-chunk나 devup route 구현으로 다시 제안하지 않는다. 특히 Mincho의 whole-artifact sharing과 devup의 atom identity/route hoisting은 서로 다른 크기의 단위를 처리한다.

C05/C08/C09/C11은 성능 병목을 확인한 뒤 진행할 규모이며, C06/C07은 CSS bytes만 줄였다고 통과시키지 않고 초기·route transition·방문한 route 전체 전송량, request 수, cascade·SSR/HMR 결과를 함께 비교한다. 이 감사에서는 해당 실험이나 성능 수치 재현을 실행하지 않았다.
