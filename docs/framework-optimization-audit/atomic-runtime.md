## 조사 범위와 판정 기준

- StyleX: Babel plugin의 entry/visitor/evaluator/shared CSS compiler, atoms transform, stylex runtime, optional injection/stylesheet helpers, Rollup/unplugin Vite 및 공통 core, CLI cache/watch, PostCSS builder/bundler, 관련 테스트와 package exports.
- Griffel: core runtime/compiler/renderer, React wrappers/SSR, 기존 Babel preset + webpack loader/extraction plugin, 새 OXC transform/evaluation/shaker + Vite/webpack plugin, CSS extraction utils, resolver, package metadata 및 관련 테스트.
- CSS Hooks: core 전체 구현, React/Preact/Solid/Qwik adapters, package exports, core browser/production tests, quickstart 및 API 문서. 사이트 자체의 UI 최적화는 라이브러리 최적화로 세지 않았다.
- 검색은 `rg --files`, `rg -n`으로 entry와 `cache`, `evaluate`, `dedupe`, `hash`, `pure`, `transform`, `insertion`, `SSR`, `watch`, `worker` 경로를 찾고 연결된 내부 helper를 읽는 방식이었다. 파일:라인은 해당 checkout 기준이다.
- **이미 있음**은 동일 목적의 메커니즘이 Mincho 소스로 확인된 경우, **부분 있음**은 적용 범위·출력 단계·증명 강도가 다른 경우, **추가 후보**는 별도 실험이 필요한 경우다. **부적합**은 Mincho의 현재 CSS/JS 계약이나 배포 목표를 그대로 유지하면서 도입하기 어려운 경우다.

## 우선순위를 둔 적용 후보

### C-A01 — 불변 scoped cx 결과를 module 초기화 이전, build-time에 bake

- 참고: SX-B08. Mincho에 table feature는 있으므로 **새 조건 테이블 기능이 아니라 table의 evaluation stage 이동**이다.
- 적용 범위: factory identity, serialized immutable `classWrites`/segments, operand strings가 모두 증명되는 `defineRules` scoped cx와 조건 table. escaped/mutable/custom cx, getter/proxy/eval/with, unknown class write provenance는 기존 fallback.
- 방식: 현재 [createTableExpression](../../packages/babel/src/defineRulesCxConditionsCodegen.ts)의 cx calls를 현재 runtime의 정확한 merge 의미로 build에서 계산한 string literal로 대체. 결과가 table뿐이면 factory/helper import와 metadata liveness도 다시 계산.
- 검증: 조건 평가 순서/횟수, shorthand-logical conflicts, inherited preset atoms, unknown classes, segment markers의 public output 계약, null/false/배열/객체와 getter bailout, CJS/ESM parity. module initialization CPU/heap, first render, JS raw/gzip/Brotli 및 build 비용을 함께 측정. 기존 class-table entry/payload cap 유지.
- 기대 방향: first-use/module-init merge 비용과 runtime helper JS 감소 가능. 조합 table로 JS가 늘 수 있으므로 무조건 활성화하지 않음.

### C-A02 — symbolically resolvable token/reference protocol 확장

- 참고: SX-B03와 GR-B04. **StyleX식 파일/export/key identity**가 Griffel의 단순 `tokens` 이름 heuristic보다 Mincho의 증명 모델에 더 잘 맞는다.
- Mincho는 이미 moduleGraph/partial evaluator/preset artifact를 사용한다. protocol로 검증된 `createVar`/theme/preset reference를 dependency 전체 실행 없이 resolved var string으로 만들 여지가 있는지 profiler로 먼저 확인한다.
- token value가 아니라 **변수 이름 자체가 계약으로 결정되는 경우**에만 적용. content-derived value/hash, side effects, mutable export, package duplicate/version 차이는 fallback. CSS provider dependency와 asset retention은 별도로 유지(SX-B19).
- 검증: alias/re-export/PnP/ESM+CJS, 동일 token 값 변경 때 consumers의 불필요 evaluation 여부, CSS value/provider 갱신은 빠지지 않는지, token package의 local override와 shadowed bindings.
- 기대 방향: dependency parse/eval 감소 가능. 아직 Mincho 관련 병목이 측정되지 않아 P2 성격이다.

### C-A03 — canonical defineRules atoms의 cross-owner 재사용 범위 실험

- 참고: SX-B05/06와 GR-B10/11. Mincho의 [canonical cache](../../packages/css/src/defineRules/utils.ts)와 [parent preset hydration](../../packages/css/src/defineRules/runtimePreset.ts)은 이미 구현이다.
- 추가 범위는 independent defineRules instances에서 같은 pure atom이 생성되는 경우다. 일반 scoped `css()`/global/keyframes 전체를 전역 atomic화하지 않는다.
- 먼저 duplicated atoms를 diagnostics로 계수. 조건 체인·property write identity·fallback/shorthand·CSS layer·asset base URL·file order barrier가 모두 같거나 안전하게 이동 가능한 atom만 공유 후보. per-origin URL 처리를 버리면 안 된다.
- library subpath imports, app lazy chunks, route/layout sharing에 필요한 CSS ownership을 보존해야 한다. 동일 CSS text가 보여도 lazy asset으로 무조건 이동시키는 것은 안전하지 않다.
- 기대 방향: 동일 declaration class/CSS 중복 감소 가능. cross-instance class identity 변화·public class strings·SSR order 계약 영향이 커서 opt-in/별도 experiment 권장.

### C-A04 — 빌드 diagnostics를 원인별로 더 자세히 분류

- 참고: GR-B17. Mincho의 [diagnostics 및 shared-analysis 보고](../compilation-performance.md)는 이미 있다. 새로운 diagnostics system 구축이 아니라 missing cause classification 여부를 확인하는 항목이다.
- profiler에 AST-only 성공, VM fallback 이유/빈도, CJS 때문에 넓어진 evaluation, export-star 때문에 넓어진 dependency reachability, hit 없는 cache key 작성량을 root cause별로 추가할 수 있다.
- 이 정보가 실제로 없는 영역에 한해 추가. 진단 비활성 비용 0에 가깝게 유지하고 build duration 합산 때 nested phase 중복을 피한다.
- GR-B08의 cache bypass는 이 진단에서 hit 없는 경로가 증명될 때만 선택적으로 검토. Mincho evaluationResultCache (`packages/integration/src/evaluationResultCache.ts:105`)의 owner replay를 일괄 끄는 것은 권장하지 않는다.

### C-A05 — closed syntax fast path의 native parser/range editor 실험

- 참고: GR-B02/03. 모든 Babel pass를 OXC로 교체하는 계획이 아니다.
- Mincho의 sourceAnalysis (`packages/babel/src/sourceAnalysis.ts:13`)는 이미 Babel immutable AST를 downstream과 재사용한다. 별도 parser를 넣어 parse가 두 번 발생하면 악화될 수 있다.
- 아주 단순한 plain module 후보 필터 또는 literals-only authoring을 parse once로 끝낼 수 있고 custom Babel config가 없는 폐쇄 경로에 한해 측정. source map, comments, evaluation order, TS/JSX/CJS/sidecar parity를 보존해야 한다.
- 실제 cold/edited/restart benchmark가 이득을 보이기 전에는 implementation 우선순위를 높이지 않는다.

### C-A06 — CSS Hooks의 boolean gate/long-expression factoring은 제한된 실험

- 참고: CH-R01/03/04. 여러 selector 조건에서 무한히 달라지는 inline values가 많은 경우 CSS expression factor가 class combination이나 많은 inline strings보다 작을 수 있다.
- Mincho 기존 static independent-branch 클래스, dynamic scalar vars, finite class tables와 같은 UI를 세 방식으로 비교한다. JS bytes만 보지 않고 SSR HTML bytes, inline custom properties 수, style recalculation, inheritance, null fallback, selector nesting, CSP 허용 모델을 함께 확인한다.
- source의 32-character threshold를 무조건 복사하지 않는다. 긴 string이 한 번만 쓰이면 hash variable 선언 때문에 오히려 커질 수 있다. 조건별 boolean variables는 기본 생성 CSS와 semantics가 달라 opt-in prototype 수준이 적절하다.

## 그대로 도입하지 않을 것

- StyleX/Griffel의 전체 CSS를 한 entry로 몰아넣는 출력: Mincho의 lazy CSS/route-layout 목적과 충돌한다. 이미 `single`/library style 분포 선택이 있으므로 통합 정책을 기본값으로 바꾸지 않는다.
- Griffel의 process-global 무제한 sequence/eval caches: Mincho에는 bounded/byte-accounted/adaptive caches가 있어 대체할 이유가 없다.
- StyleX 전체 atomic/property-priority/shorthand 제한을 일반 Mincho CSS에 강제: authored CSS order와 scoped selectors 계약을 바꾼다. defineRules 경로의 안전한 atoms만 별도 검토한다.
- css-hooks처럼 모든 static styles를 inline으로 전환: CSS asset 캐시, SSR HTML payload, 현재 static extraction의 장점을 잃을 수 있다.
- runtime stylesheet renderer/React useInsertionEffect 도입: Mincho static production pipeline에는 삽입할 runtime styles가 없어 새 runtime 비용이 된다. widget/별도 runtime 모드를 사용자가 요구할 때 다시 검토한다.
- 새 OXC resolver를 기본 provider로 교체: Griffel 소스의 alias/PnP/condition 지원은 Mincho native bundler-provider 계약보다 단순하다.
- 단순 variable 이름으로 token folding: shadowed/local `tokens`의 의미를 바꿀 수 있다. import binding·protocol·버전 증명이 필요하다.
- selector pruning을 class string grep로 구현: 이 조사에서 namespace JS DCE와 actual CSS liveness는 분리되어 있다. Mincho에서도 CSS scope/composition/authoring effects가 생존하는지 증명해야 한다.

## 테스트 근거와 남은 불확실성

- StyleX는 props/static/dynamic fallback, atom dedupe, process sorting/media query, dynamic pseudo-element inheritance tests를 읽었다. package의 외부 `styleq` 코드는 checkout에 없어 그 내부 cache 수명·알고리즘을 검증하지 않았다.
- Griffel은 transform static/VM/token tests, multiple-renderer·merge/RTL/reset tests, Vite all-chunk/dedup/stats tests, SSR at-rule/duplicate flush tests를 읽었다. 이들의 존재는 assertion 계약 근거이며 이번 조사에서 통과했다는 결과가 아니다.
- CSS Hooks는 Playwright 기반 selector/at-rule/boolean/scope/starting-style/revert-layer 사례와 production whitespace/hash/merge tests를 읽었다. FAQ 성능 설명은 재측정하지 않았다.
- Mincho 코드 비교는 docs 세 파일과 실제 sourceAnalysis/moduleParser/evaluationResultCache/IR/distChunk/defineRules cache+artifact+cx/조건 table/codegen을 대조했다. 후보들의 최종 우선순위는 부모의 다른 여섯 framework 조사 및 Mincho 전체 분석과 함께 결정해야 한다.
