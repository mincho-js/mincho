# Theme UI Presets

The preset package supplies Theme UI v0.17.4 token values, compiled themes, and native Mincho authoring definitions. `@mincho-js/theme-ui` supplies contracts, Theme Spec mappings, and optional normalization; `@mincho-js/preset-theme-ui-react` adds components, variant groups, and scoped React JSX types.

## Install and configure [#install-and-configure]

In a React app, put the Mincho plugin before the React plugin to compile co-located styles. Keep the Vanilla Extract plugin for shared `.css.ts` themes. Import the preset stylesheet once to load the theme variables. Keep `@mincho-js/react` as an application dependency for the shared compiled React runtime.

```sh
npm install @mincho-js/css @mincho-js/react @mincho-js/theme-ui @mincho-js/preset-theme-ui @mincho-js/preset-theme-ui-react @vanilla-extract/css
npm install -D @mincho-js/vite @vanilla-extract/vite-plugin @vitejs/plugin-react
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { minchoVitePlugin } from "@mincho-js/vite";
import { extractCalls } from "@mincho-js/preset-theme-ui-react/config";
import { vanillaExtractPlugin } from "@vanilla-extract/vite-plugin";

export default defineConfig({
  plugins: [
    minchoVitePlugin({
      jsxCssProp: { importSource: "@mincho-js/preset-theme-ui-react" },
      extractCalls,
    }),
    vanillaExtractPlugin(),
    react({ jsxImportSource: "@mincho-js/preset-theme-ui-react" }),
  ],
});
```

Set TypeScript's scoped JSX source to the same package:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@mincho-js/preset-theme-ui-react"
  }
}
```

## Use component variants [#use-the-shared-definition]

`@mincho-js/preset-theme-ui-react` adds `styled` and `components()` to the native `base`, `system`, and `dark` definitions. `components()` binds standard primitives such as `Box`, `Text`, `Heading`, `Button`, and `Link` to the selected theme. It preserves the preset's original groups and merges your component variants into them.

The configured `extractCalls` map compiles `components()`, `styled`, `css`, `rules`, and `cx` calls directly in the component's `.tsx` file. Shared definitions can also live in `.css.ts`. `/config` is plain data and does not load theme CSS or authoring code in Node.

[Theme UI component variants](https://theme-ui.com/components/variants) use group-relative names such as `<Heading variant="display">` or full paths such as `variant="text.display"`. A component looks in its own group first, then at the full theme path. A variant can inherit another through its `variant` property; later properties override the inherited values. The default `Heading` uses `text.heading`, `Button` uses `buttons.primary`, and `Link` uses `styles.a`.

```tsx
// Card.tsx
import { system, systemClass } from "@mincho-js/preset-theme-ui-react";
import "@mincho-js/preset-theme-ui/styles.css";

const { Box, Heading, Button } = system.components({
  buttons: {
    primary: { color: "background", bg: "primary" },
    secondary: { variant: "buttons.primary", bg: "secondary" },
  },
});

export function Card() {
  return (
    <Box
      as="section"
      className={systemClass}
      css={{ color: "text", bg: "background", p: { base: 3, _md: 4 } }}
    >
      <Heading variant="display">A shared vocabulary</Heading>
      <Button variant="secondary">Create project</Button>
    </Box>
  );
}
```

Here `text.display` comes from the original system preset, while `buttons` is application configuration. Component variant props select compiled recipes at render time. JSX `css` uses the system definition and accepts native Mincho condition objects. For base, dark, or custom contracts, put semantic token styles in that definition's component groups or use classes generated by its own `css()` function.

## Package responsibilities [#package-responsibilities]

`styles.css` contains only the theme variables and system color modes. It does not generate document selectors, containers, headings, or application recipes. The consumer compiles those styles through the exported definition or `components()` call. React components use the resulting classes and recipe selectors; the component builder does not add global document styles.

The root also exports `baseClass`, `systemClass`, `darkClass`, their `*Vars` and `*Contract` values, and `systemModeClasses`. JavaScript imports do not load CSS. Reading compiled theme data in Node/SSR needs no build plugin; calling `css()` or `rules()` belongs in a style build.

`system.preset` is Mincho's native compiled-style artifact, not a theme value object. Use `defineRules.extends(system, ...)` to extend the authoring vocabulary:

```ts
import { defineRules } from "@mincho-js/css";
import { system } from "@mincho-js/preset-theme-ui";

const { css } = defineRules.extends(system, {
  properties: { display: ["grid", "flex"] },
});
export const layout = css({ display: "grid", gap: 3, color: "primary" });
```

## Customize tokens and conditions [#customize-tokens-and-conditions]

`/presets` exports normalized `baseTokens`, `systemTokens`, `darkTokens`, and `systemModes` as plain data. Create an independent theme using the original Mincho `theme()` function, then bind its variables with `themeSpec()`. These styles do not require the shipped stylesheet.

The type contracts preserve upstream differences: base has `fontWeights.bold`, system and dark have `fontWeights.display`, system has `colors.accent`, and dark has `colors.purple`.

```ts
// custom.css.ts
import { theme, defineRules } from "@mincho-js/css";
import { themeSpec } from "@mincho-js/theme-ui";
import { systemTokens, systemModes } from "@mincho-js/preset-theme-ui/presets";

const tokens = {
  ...systemTokens,
  colors: { ...systemTokens.colors, primary: "rebeccapurple" },
};
export const [themeClass, vars, contract] = theme(tokens);
export const [darkClass] = theme.extends(contract, {
  ...systemModes.dark,
  colors: { ...systemModes.dark.colors, primary: tokens.colors.primary },
});
const { css, rules, cx } = defineRules(themeSpec(vars, { tablet: "48em" }));

export const panel = cx(
  themeClass,
  css({ bg: "background", _tablet: { p: 4 } }),
);
export const action = rules({ base: { bg: "primary", color: "background" } });
```

For React, pass your native definition and variant groups to `createComponents()`. The builder is extracted in the component file and uses your variables and conditions:

```tsx
// CustomButton.tsx
import { defineRules } from "@mincho-js/css";
import { themeSpec } from "@mincho-js/theme-ui";
import { createComponents } from "@mincho-js/preset-theme-ui-react";
import { vars } from "./custom.css";

export const { Button } = createComponents(
  defineRules(themeSpec(vars, { tablet: "48em" })),
  {
    buttons: {
      primary: {
        px: { base: 2, _tablet: 4 },
        color: "background",
        bg: "primary",
      },
      secondary: { variant: "buttons.primary", bg: "secondary" },
    },
  },
);
```

Apply the custom theme class above the component. Its group styles use the custom contract, while the package's default JSX `css` source remains bound to system.

## Scales and color modes [#scales-and-color-modes]

The 16 Theme Specification scales map to CSS properties. `p: 2` selects `space[2]` (`8px`), while `mx: -2` uses its negative value. Indexed scales retain their bounds; dotted paths select nested tokens. Length tokens include units; weights and line heights remain unitless. Provided scales restrict values to their token names; absent scales accept ordinary CSS.

`p` expands through `px` and `py` to the four physical padding properties. Margin shortcuts follow the same pattern. For example, `cx(css({ p: 2 }), css({ px: 3 }))` replaces left and right padding while keeping top and bottom padding at `space[2]`. Styles in separate conditions retain their own values.

Default conditions are `_sm: 40em`, `_md: 52em`, and `_lg: 64em`. Custom breakpoints replace them. Write responsive values as Mincho condition objects, for example `fontSize: { base: 3, _sm: 4 }`. Use these condition objects in custom component groups and JSX `css` as well. The original responsive arrays in shipped presets are converted internally; custom groups use Mincho conditions.

`systemModeClasses` has `default`, `dark`, `deep`, and `swiss` class names. Replace the active class to switch modes. Components keep semantic values such as `color: "text"` and `bg: "primary"`; the class changes the values behind those tokens, following [Theme UI's color-mode model](https://theme-ui.com/color-modes).

For token values, `/presets` exports `systemTokens` for the default mode and `systemModes.dark`, `systemModes.deep`, and `systemModes.swiss` for named modes. Use `theme.extends(systemContract, values)` for a mode that shares the compiled system variables. OS preference and storage belong to the application.

## Normalize original tokens [#normalize-original-tokens]

Shipped tokens are already normalized. For original Theme UI data, `normalizeTheme()` converts length units and completes color modes without generating CSS. It returns `{ tokens, modes }`. Token normalization is separate from component compilation. Use `components()` for preset component groups and variant references; use native `css()`, `rules()`, and `styled` for your own definitions. The React preset does not provide a Theme UI provider or an `sx` runtime.

Public types use Mincho's `@mincho-js/csstype`; upstream types are development-only compatibility references. Theme UI and Emotion styling packages are not consumer dependencies. Validation uses TypeScript 5.9.3. Try the React example with `yarn workspace @examples/theme-ui dev`.

```ts
import { theme } from "@mincho-js/css";
import { normalizeTheme } from "@mincho-js/theme-ui";

const normalized = normalizeTheme({
  space: [0, 4, 8],
  colors: { text: "#111", modes: { dark: { text: "#fff" } } },
});
export const [light, vars, contract] = theme(normalized.tokens);
export const [dark] = theme.extends(contract, normalized.modes.dark);
```
