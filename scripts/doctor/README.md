# Yarn Doctor

`yarn doctor` runs the pinned `@yarnpkg/doctor` against this repository and checks
both warnings and errors against `exceptions.json`. CI runs it after immutable
installation, together with `yarn test:doctor`. No extra download is needed.
`yarn doctor:raw` shows the upstream report, including the reviewed false positives.

Each JSON exception has a unique, stable `id` and identifies one file, diagnostic
severity and message, exact trimmed source line, expected occurrence count, and
reason. Keep the ID when editing a rule so CI logs remain recognizable.
Line numbers may shift, but
changed source, additional occurrences, new diagnostics, and unused exceptions
fail the check. An incomplete scan, malformed output, or unexpected process exit
also fails. Review the current code before changing an exception; do not regenerate
the list simply to make CI pass.

`expires` is an optional calendar date in `YYYY-MM-DD` format. A rule is valid
through that date in UTC and fails from the following day, even if its diagnostic
has disappeared. Invalid dates fail configuration validation. Omit `expires` or
set it to `null` only for deliberately permanent exceptions. The existing rules
have an initial review deadline of `2026-12-31`; review each rule before extending
its deadline, rather than automatically moving all dates forward.

For example:

```json
{
  "id": "site-mdx-components-import-01",
  "file": "site/mdx-components.tsx",
  "type": "error",
  "message": "Undeclared dependency on mdx",
  "source": "import type { MDXComponents } from 'mdx/types'",
  "count": 1,
  "reason": "This type-only import is supplied by the declared @types/mdx dependency.",
  "expires": "2026-12-31"
}
```

The command prints each decision with its rule ID where applicable, followed by
totals for each category:

| Label       | Meaning                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------ |
| `ALLOW`     | The diagnostic matches a current rule's exact file, message, severity and source.                |
| `NEW`       | No unexpired rule matches the diagnostic.                                                        |
| `EXPIRED`   | A rule's deadline has passed, regardless of whether it matched.                                  |
| `STALE`     | A rule matched fewer occurrences than its exact `count`, including zero.                         |
| `BROAD`     | A rule matched more occurrences than its exact `count`.                                          |
| `AMBIGUOUS` | Different rule IDs define the same exact match; rejected before applying exceptions.             |
| `ERROR`     | Invalid configuration, malformed output, incomplete scanning, or unexpected process termination. |

Only `ALLOW` is successful; every other category fails the command. Duplicate IDs
are configuration errors. Unlike a maximum-only policy, decreasing occurrence
counts also require review. The original upstream report remains available via
`yarn doctor:raw`.

The reviewed exceptions cover:

- Consumer fixtures whose manifests and dependencies are generated by
  `scripts/package-contract/index.ts` before isolated npm builds.
- The type-only `mdx/types` import supplied by the site's declared `@types/mdx`.
- CSS and TypeScript build peers already declared in private applications'
  development dependencies. These applications build before deployment.
- Deliberate node_modules compatibility fixtures, boundary checks, diagnostic
  labels, an ESLint ignore pattern, and isolated npm consumer paths.
- esbuild syntax-loader options mistaken for Webpack loader packages, and Vite's
  explicit `preview` command mistaken for an automatic lifecycle hook.

The Yarn patch for Doctor 4.0.7 reads normalized descriptors from the installed
resolution map, including package extensions and pinned versions, instead of
trying to resolve bare version ranges against registry resolvers. It also adds
JSON output with warnings, source locations for lifecycle warnings, and a
completion record, and reports exceptions the upstream scanner silently catches.
Keep these changes when updating Doctor, or verify that upstream provides the
equivalent behavior before removing the patch.

The checker tests ensure that unknown imports and warnings, expired or stale
exceptions, invalid dates, duplicate IDs, overlapping rules, changed type-only
imports, excess diagnostics, and broken scanner output fail.
`yarn test:all` and the production package contract remain independent checks of
the actual builds and published dependency contracts.
